What is graph-based inference?

A graph is a production line. A model is a part on the shelf.

If you know vLLM

There, the model is a deployment. Here, it is a part pulled from the shelf per job.

If you don't

A prompt box is a vending machine. A graph is a production line: change one station, only that one reruns.

  • One job: 10+ images, text, LoRAs, 2–3 models, 40 nodes.
  • Most nodes are not inference.
  • Templates: built by others, or yourself. The shelf only grows.

Why not an engine per model?

Residency scales with the catalog. The pool scales with concurrency.

  • Every model on an engine: +$713/mo each.
  • The pool: flat.
  • The marginal model: a machine there, a disk here.

What does the repo add beyond the Omni bridge?

The production layer: queue, isolation, storage, scale

  • WebSocket in, Redis queue out. No browser touches a worker.
  • Shared storage: a model pulled once is there for everyone.
  • No shared storage? S3 + node cache. Hundreds of designers, same shape.
  • Workers unreachable by design. SSO, audit, showback, quota.

Where does vLLM Omni fit? Does this touch the application layer?

Two tiers, one stack. Showback decides when a model moves.

  • Engine = throughput tier. Pool = flexibility tier.
  • One model dominates showback → give it an engine.
  • Omni is one more node on the canvas. The bridge exists today.
  • ComfyUI stays upstream's app. This repo is wiring.
